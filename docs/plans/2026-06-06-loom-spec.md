# Loom — Design Spec

> Working name. Loom is the rebase-based orchestration layer that sits on top of
> **quilt** (merge-based combination probe) and **rightwayc** (doctrine + skills +
> per-task reflection). This spec covers **only the new components**. quilt and
> rightwayc internals are dependencies, referenced by their public primitives and
> never re-specified here.

---

## 1. Purpose

Maintain a continuously-rebased, all-commits-green, tests-first integration line
(`staging`), promote a stress-validated subset of it to `next_staging` by
fast-forward, and maintain a zoo of long-lived design-alternative branches kept
green against `next` by an agent swarm — so that arbitrarily large design changes
can be composed and landed on the strength of a green full-CI run.

quilt answers *"which combinations of branches are mutually viable"* (cheap,
merge-based, order-insensitive). Loom answers *"given a viable combination, what
ordering makes it all-commits-green and bisectable"* (expensive, rebase-based,
order-sensitive) and owns the tiered promotion, the zoo maintenance, and the
agent loops.

---

## 2. Governing principles

1. **Increment-set is the source of truth; branches are projections.** Loom stores
   an increment set + an inferred dependency DAG + a policy. Every integration
   branch is `materialize(sort(set, DAG, policy))`, recomputed and force-pushed
   when the set changes. Force-push is intrinsic, not a smell.

2. **Deterministic by default; LLM only at a decision.** Everything that can be
   computed by a Python/JS script is. An LLM is invoked *only* at a named decision
   point, off the happy path, via a fixed shell contract (§7). A clean merge that
   clears the ladder promotes with zero LLM calls.

3. **Green by truncation, never by silent fixing.** The published green branch is
   the maximal green prefix of the solved order. Everything past the first failure
   is *parked* as a work item, not materialized. The branch is green by
   construction.

4. **No responder self-certifies.** Every LLM responder is gated by re-running the
   deterministic emitter that produced its signal, and its output re-enters at the
   *top* of the gate ladder (cache makes unaffected rungs free).

5. **Coverage is the spec.** Green-on-full-CI is the safety certificate for a
   promotion of any size. The system amplifies both the value of coverage and the
   blast radius of its gaps; the test-integrity auditor (§6.1) is therefore
   load-bearing, not optional.

6. **Safety rails are gates, not conventions.** No component ever auto-pushes a
   remote. All push proposals are surfaced for interactive approval; push URLs
   contain `hila-shemer`, never `Majestic`; if blocked, deliver patch artifacts.

## 3. Tier model

| Tier | Invariant | Rewrite | LLM cost |
|------|-----------|---------|----------|
| **zoo** | green on inherited (`next`) tests is the *target*; transient red allowed; per-branch DoD = which test sets must end green | rebased continuously on moving `next` | maintenance loop |
| **staging** | all-commits-green (cheap gate ladder), bisectable, tests ordered first | force-pushed/reordered freely **above the frozen floor only** | seam-search at each promotion |
| **next_staging** | everything staging guarantees **plus** stress-passing at milestone commits | fast-forward only | stress at milestones |

- `next_staging` advances by **fast-forward from staging**, so it inherits
  green-on-every-commit for free (commit identity preserved → gate cache hot). The
  *only* marginal work is the stress (`long`) gate at milestones.
- `next_staging`'s tip is a **frozen floor**: staging may rewrite only the suffix
  above it. The seam-search working set is exactly that mutable suffix and shrinks
  from below as milestones validate.
- A milestone is, by default, the tip of a fully-absorbed increment. Bisect
  granularity is then per-commit for cheap regressions, per-increment for stress
  regressions.

## 4. Data model

Source-of-truth state lives in **SQLite** (single-writer, crash-durable; fits the
interruptible environment). Code objects live in **git** (`refs/loom/*`). All job
results are content-addressed and idempotent so a crashed tick recomputes only
what is missing.

### 4.1 Increment

```
increment {
  id
  tier_target:    zoo | staging
  patches:        { repo -> patch }      # for staging: small diff + small cross-repo diff only
  priority_class: test | invariant | fix | feature | rewrite
  deps:           [increment_id]         # HINT ONLY — ground truth is inferred (§6.2)
  dod:            { required_test_sets }  # zoo branches
  base:           next@<sha>
  oracle_ref:     <differential test id> # rewrites / cross-language
  status:         green | red(tests) | building | parked
  stability:      churn metric
  patch_id:       git patch-id --stable  # branch identity for cache keys
}
```

### 4.2 Inferred dependency DAG

Edges `X -> Y` ("X red unless Y precedes"), discovered by seam-probing (§6.2),
cached and durable until X or Y changes. This is the empirically-learned form of
the `deps` hint.

### 4.3 Per-commit gate cache

`(commit_tree_sha, gate) -> result`. Distinct from quilt's per-merge-point cache;
this one serves the linear line. Fast-forward into `next_staging` is a pure
cache-hit operation.

### 4.4 Journals (see §8)

```
role_journal {
  role, task_type,                 # e.g. (resolver, conflict), (reviewer, fix-review)
  kind:        structured | narrative
  pattern:     <retrieval key>     # for structured: conflict/finding shape
  lesson:      <text or action>
  recurrence:  int                 # hypothesis at 1, rule at N
  refs:        [files/symbols]      # for decay detection
  scope:       role-local | project-global | doctrine-upstream
}
```

## 5. The decision-call boundary (per component)

Each component below is specified as **Automated** (script, always) + **Decision
hook** (LLM, only when reached). If a component has no decision hook it is pure
script and never calls a model.

---

## 6. Workflows (deterministic core + decision hooks)

### 6.1 Test-integrity auditor  `[new]`  — Python, LLM: Haiku (rare)
**Keystone.** Validates that a green signal is real before it is trusted anywhere.
- *Automated*: expected-vs-actual test count, exit codes, that the binary was
  rebuilt from the candidate tree, that coverage intersected the diff, that no
  tests silently skipped/xfailed.
- *Decision hook*: only when the deterministic checks are *inconclusive* (novel
  harness output) → Haiku classifies real-green vs fake-green.
- *Interfaces*: runs after every gate-ladder execution; a fake-green voids the
  cache entry and re-enqueues the gate.

### 6.2 Linearizer + seam-search  `[new]`  — Python, LLM: Haiku classifier
**Largest new build.** Turns a viable combination (from quilt) into an
all-commits-green, tests-first, bisectable series on `staging`.
- *Automated*: candidate ordering by `(priority_class, stability, -size, age)`;
  apply order; run selective gates per commit; detect the maximal green prefix;
  identify red **seams**; record inferred DAG edges; try reorder before any repair
  (reorder is non-destructive; repair is debt); on series-level cycle drop to
  commit-level interleave; emit `split-needed` if still cyclic.
- *Decision hook*: at a red seam, **only** to classify *hard-dependency* (→
  reorder) vs *incidental-conflict* (→ repair) — the one judgment a script can't
  make. Haiku, `(seam diff) -> {hard|incidental, easy_fix:bool}`.
- *Tests-first*: a test-only commit that is green on the current base is hoisted
  to the front and merged immediately (queue-skip).

### 6.3 Regression-lock harvest  `[new]`  — Python, no LLM
- *Automated*: scan injected branches for commits whose tree restricted to
  test-paths applies on `staging` and passes; lift them to base; merge
  immediately; rebase the donor branch. (The classifier and the lift-condition
  coincide.)
- Note: harvesting/landing an invariant changes the base tree → invalidates the
  combination cache → batch these at an epoch boundary, never dribble.

### 6.4 Maintainer loop  `[new]`  — Python, no LLM (delegates conflicts to §6.6)
- *Automated*: for each zoo singleton, rebase onto the moving `next`; run its DoD
  gates; on success update its tip in quilt's `branches` list; on conflict/red
  emit the standard signal into the loop. Keeps the lattice basis current so
  on-demand composition is cheap.
- *Scaling*: maintain N singletons (linear). Compositions are materialized on
  demand (rebase Y onto `next_X`), never enumerated beyond quilt's N≤5 window.

### 6.5 Port-forward (cross-language / cross-project rebase)  `[new]`  — Python harness, LLM: Opus
- *Automated*: detect what changed in `next`/source since fork (new/changed
  behaviors and their oracle cases); run the differential oracle against the
  target; identify behaviors not yet matched.
- *Decision hook*: Opus performs the actual porting development for unmatched
  behaviors. Done = ported behavior matches the oracle. (Source diffs do not
  rebase across a language boundary; oracle cases do.)
- Output is a **branch**, which re-enters the front of the pipeline via §6.2/§6.3.

### 6.6 Promotion: ff + milestone-stress  `[extend quilt freeze/advance]`  — Python, no LLM
- *Automated*: pick the staging milestone that cleared the candidate gate; run the
  stress (`long`) gate via quilt's async `untested → inflight → validated`;
  on `validated`, fast-forward `next_staging`; on stress-fail, hold `next_staging`,
  let staging run ahead, route the failure to the debugger (§6.10) for attribution
  + fix on the mutable suffix, re-stress.

### 6.7 next_staging propose-push  `[new]`  — Python, no LLM. **Hard safety gate.**
- *Automated*: never pushes. Surfaces the materialized result + proposed branch
  name for interactive approval; verifies the push URL contains `hila-shemer` and
  not `Majestic`; on any block, emits patch-file artifacts instead. local-staging
  (`refs/loom/staging`, local) is never pushed.

### 6.8 Coverage gate  `[new]`  — Python, no LLM
- *Automated*: pass/fail coverage bar as a ladder rung; additionally certifies
  that seam tests at each commit actually exercised the dependency they could trip
  (validity input for §6.2's inferred DAG).

### 6.9 Release-notes  `[new]`  — Python hook, LLM: Haiku
- *Automated*: collect the increment metadata + diffs at promotion.
- *Decision hook*: Haiku summarizes into a changelog entry. Generative, never a
  gate (it cannot "fail"); a post-promotion hook, sibling to §6.6.

### 6.10 Cross-repo coordination  `[new, later]`  — Python, no LLM
- *Automated*: atomic dual-repo small-change landing; detect cross-pipeline
  dependency cycles and refuse rather than deadlock.

## 7. The universal LLM decision contract

All decision hooks use one interface (quilt's model, generalized):

- Invocation: a configured shell command (`claude -p --model <tier>`), prompt on
  **stdin**, structured **JSON on stdout** (classifiers/attributors), or in-place
  worktree edits (resolver/fixer/debugger/porter).
- Context injected by the caller: the global journal + the role-local experience
  retrieved for this `(role, task_type, files)` (§8). ~2k tokens of role context
  per call is acceptable and improves quality; freshness/trim (§8) matters.
- The script parses the result, **re-runs the emitter to verify**, and proceeds or
  loops. No model output is trusted without a deterministic re-check.

## 8. Agents (off the happy path; selected by signal type)

Agents are packaged as **rightwayc commands/skills** (their home) even though
their output is governed by §8.4 and does not flow into rightwayc's own content.

### 8.1 Roles

| Role | Class | Model | Status | Deterministic core / decision boundary |
|------|-------|-------|--------|-----------------------------------------|
| Triage | router | Haiku | extend quilt | route trivial/moderate→responder, complex→escalate/park; add the *review-findings* signal type |
| Resolver | responder | Sonnet | extend quilt | git-mediate-gated; LLM only to resolve; learned-rerere journal injected |
| Debugger | responder | Sonnet/Opus | extend quilt diagnose | diagnose attributes (cheap); fix at the **source branch** when attributed there (→ quilt backprop), at the seam only otherwise |
| Fixer | responder | Haiku (style) / Sonnet (correctness) | new | answers review/style findings; re-gated by the emitting reviewer |
| Code review | emitter | Sonnet→Opus | new | emits typed findings; partitioned new-code vs fix-review |
| Style review | emitter | Haiku | extend (wrap rw-c-review) | wire rw-c-review as a gate that emits findings |
| Extraction | producer | Sonnet | new | liftability is script (§6.3 generalized to intra-branch subsets); LLM only for "worth landing alone?" |
| Porting | producer | Opus | new | §6.5 |

### 8.2 The loop (one shape, three instances)

`emitter → typed signal → triage → responder → re-run emitter`

- Emitters: rebase (→conflict), gate ladder (→test-fail), code/style review
  (→findings). rebase and the ladder are deterministic; reviewers use an LLM only
  to *produce* findings.
- A response re-enters at the **top** of the ladder (cache keeps it cheap) to
  prevent whack-a-mole (a conflict fix breaking a test, a test fix tripping style).
- Convergence = full ladder clears with no new signal. Non-convergence after a
  bounded retry escalates Haiku→Sonnet→Opus, then **parks** the increment (§ green
  by truncation). A stuck loop never blocks the line.

### 8.3 Extraction detail
Intra-branch dependency inference (same engine as §6.2, pointed inward): find the
maximal subset of a branch's own commits that lifts onto staging and clears the
cheap ladder. Flavors: test-extraction (= §6.3, auto), infra-extraction
(behavior-neutral commits), fix-extraction (bugfix + its lock as a unit).

## 9. Memory pipeline

Three scopes, three cadences. The continuous per-task reflection-append already
exists in rightwayc; Loom adds compaction and promotion + retrieval.

### 9.1 Scopes
- **role-local** — `(role, task_type)`-keyed experience for *this* codebase.
- **project-global** — useful to all roles on *this* codebase; Majestic-specific
  allowed; **stays local**, always loaded (small, strictly gated).
- **doctrine-upstream** — generic, project-internal-free; the only scope that may
  reach rightwayc, behind the §8.4 leak gate.

### 9.2 Retrieval (resolves global pollution)
- global: small, always in context.
- role-local: large, indexed, **retrieved by relevance** to the current signal —
  not loaded wholesale. Structured experience (pattern→action) retrieved by
  similarity; narrative reflection used for context-priming.

### 9.3 Compaction  `[new]`  — nightly, per-role, Haiku
Dedup restatements, merge duplicates (increment recurrence), supersede contradicted
lessons, evict lessons referencing dead code. Recurrence is the signal it produces.

### 9.4 Promotion  `[new]`  — weekly OR recurrence-threshold, Opus
Promote a lesson when it is durable, non-redundant, and **cross-role recurrent**
(two roles independently learning the same thing). Evicts what it supersedes.
Roles share *only* through global; no middle tier.

### 9.4 Leak gate (project-global → doctrine-upstream)  **Hard safety gate**
A sanitization-and-generalization step, never a copy. Project-specific lessons stay
local; only the *generic* form may be staged for upstream. The job **stages**
upstream candidates and never pushes — promotion follows §6.7's rules.

## 10. Scheduler

- Job scheduler over a **`git worktree` pool**, not a monolithic tick. Long jobs
  (stress, big composition) run in parallel worktrees; the only serialized point is
  the per-ref write at promotion (git enforces per-branch exclusivity).
- `tick` advances one ready job; reuse quilt's K-bound on concurrent heavy tests.
- **Reflow epoch**: freeze the solved plan for an epoch; agents complete rebases
  against the frozen plan; results accepted only if the epoch has not rolled, else
  re-queued. Prevents thrash under continuous force-push.
- All jobs idempotent, keyed on tree-hash; crash-resumable.

---

## 11. quilt / rightwayc interface points (dependencies, not in scope)

- **Consume**: quilt merge-tree probe, gate ladder + content cache, `tick`/K-bound,
  `triage`/`resolve`/`diagnose`, `poison`+cascade, `freeze`/`advance`, `backprop`,
  `refs/quilt/*`.
- **Feed**: maintainer (§6.4) writes current zoo tips into quilt's `branches`; Loom
  adds review/style/coverage rungs to the gate ladder; promotion (§6.6) drives
  freeze/advance; debugger (§8) routes source-branch fixes through backprop.
- **rightwayc**: hosts the agent commands/skills (incl. rw-c-review) and the
  existing per-task reflection-append; receives only §9.4-sanitized doctrine.

---

## 12. Build order

1. **Test-integrity auditor (§6.1)** — everything trusts the green signal.
2. **Linearizer + seam-search (§6.2)** + per-commit gate cache (§4.3) — no
   bisectable staging without it; largest build.
3. **Promotion ff + milestone-stress (§6.6)** + propose-push gate (§6.7).
4. Single-branch path end-to-end: harvest (§6.3) → linearize → stage.
5. Agent loops (§8) incrementally — each is cheap once 1–3 are solid.
6. Memory compaction/retrieval (§9.2–9.3), then promotion + leak gate (§9.4).
7. Maintainer loop + zoo composition (§6.4), then port-forward (§6.5).
8. Cross-repo coordination (§6.10) last.

---

## 13. Decisions to confirm (flagged, not assumed)

- **Milestone spacing** — default = tip of each absorbed increment. Wider spacing
  = fewer stress runs, coarser stress-bisect.
- **Engine language** — Python to match quilt assumed; JS acceptable for any
  dashboard/observability surface.
- **Triage routing** — heuristic-first with LLM only on ambiguous signals, vs LLM
  on every signal. Heuristic-first is cheaper and is the §2.2-consistent default.
- **Cross-repo cycle policy** — refuse-and-park assumed (§6.10); alternative is a
  human-arbitrated break.
